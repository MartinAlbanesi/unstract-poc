# Unstract OSS Extraction POC

Demo proving Unstract Open Source Edition extracts structured JSON from
Argentine documents (facturas, remitos, cartas de porte) via LLMWhisperer
OCR + Gemini LLM, served as a REST API and called from a Python client.

> Status: complete — platform bootstrap, Prompt Studio schemas/deployments,
> and the Python extraction client (with tests and live E2E verification)
> are all in place.

## Pinned release

`unstract/` is a gitignored, vendored shallow clone of
[Zipstack/unstract](https://github.com/Zipstack/unstract), pinned to
**`v0.186.1`** (never `latest`). The tag is set in `bootstrap.ps1` and
reproduced by cloning — it never enters this repo's git history.

## Requirements

- Windows with Docker Desktop (12GB+ RAM allocated), no WSL2 distro required
- Git, Python 3 on `PATH`
- Port 80 free (plus the platform's other ports — see `bootstrap.ps1`)

## Quick start

```powershell
.\bootstrap.ps1          # clone pinned tag, set up env files, docker compose up -d
.\healthcheck.ps1 -Wait 600   # poll until healthy (first boot can take a while)
```

Then visit `http://frontend.unstract.localhost` (login: `unstract` / `unstract`).
Use this hostname, not the remapped `localhost:3100` — the app is served
through Traefik, which routes `/api/v1`, `/deployment`, and `/public` to the
backend under the same host; hitting the frontend container's own port
directly skips that routing and login/API calls 404. Modern browsers (and
this host's resolver) resolve `*.localhost` to loopback natively — no hosts
file entry needed.

Safe to re-run `bootstrap.ps1` at any time — every step is guarded and a
rerun on an already-running platform is a no-op.

## Rollback

```powershell
docker compose -f unstract/docker/docker-compose.yaml down -v
Remove-Item -Recurse -Force unstract
```

Then delete the generated `.env` files under `unstract/` (removed along with
the directory above) and re-run `bootstrap.ps1` to restore.

## Setup and API keys

Prompt Studio and the 3 API deployments (`factura`, `remito`,
`carta-porte`) are configured manually in the UI — see
[`deployments/deployment-config.md`](deployments/deployment-config.md) for
the exact click-by-click steps and adapter/project layout. You need two
free-tier external keys before doing that setup:

- **Google AI Studio (Gemini)** — used for both the LLM and embedding
  adapters. Get a free key at https://aistudio.google.com/apikey.
- **LLMWhisperer** — used for the OCR/text-extraction adapter. Free tier is
  capped at **100 pages/day**. Sign up at the LLMWhisperer developer portal
  (avoid accessing the signup page through a `translate.goog` proxy URL —
  it breaks; use the real domain or your browser's native translate).

Enter both keys directly into the Prompt Studio adapter forms in the UI —
they are encrypted at rest by the platform (`ENCRYPTION_KEY`, generated by
`bootstrap.ps1`) and never touch this repo.

Once the 3 APIs are deployed, generate a bearer API key per deployment
("Manage Keys" in the API Deployments screen) and put them in
`deployments/.env` (gitignored — copy `deployments/.env.example` as the
template):

```
UNSTRACT_BASE_URL=http://frontend.unstract.localhost
UNSTRACT_ORG=mock_org
FACTURA_API_NAME=factura
FACTURA_API_KEY=<paste from Manage Keys>
REMITO_API_NAME=remito
REMITO_API_KEY=<paste from Manage Keys>
CARTA_DE_PORTE_API_NAME=carta-porte
CARTA_DE_PORTE_API_KEY=<paste from Manage Keys>
```

`client/client.py` loads this file at runtime via `python-dotenv` — the
keys are never read or transmitted by anything other than the running
Python process.

## Demo runbook

```powershell
# 1. Bring the platform up (idempotent, safe to re-run)
.\bootstrap.ps1
.\healthcheck.ps1 -Wait 600

# 2. One-time manual setup (see deployments/deployment-config.md):
#    configure the 4 adapters + 3 Prompt Studio projects + 3 API
#    deployments in the UI at http://frontend.unstract.localhost,
#    then fill in deployments/.env with the generated API keys.

# 3. Install client dependencies
pip install requests python-dotenv pyyaml pytest requests-mock

# 4. Run the client against a real document (async: submits, polls, prints JSON)
python client/client.py --type factura --file "Documentos/Demo OCR 1 - Fecha 2026-03-26/Factura_C_1.pdf"
python client/client.py --type remito --file "Documentos/Demo OCR 1 - Fecha 2026-03-26/Remito_R_1.pdf"
python client/client.py --type carta_de_porte --file "Documentos/Demo OCR 1 - Fecha 2026-03-26/CARTA_DE_PORTE_1.pdf"

# 5. Validate a result against its schema contract (lenient — tolerates OCR noise)
python -c "import json,sys; sys.path.insert(0,'client'); from validate import validate_extraction, schema_path_for; \
data = json.load(open('output.json', encoding='utf-8')); \
print(validate_extraction(data, schema_path_for('factura')) or 'PASS')"

# 6. Run the test suite
cd client && python -m pytest tests/ -q
```

**Exit codes** (`client.py`): `0` success, `1` invalid/missing input file,
`2` connection or non-2xx HTTP error, `3` extraction failed or timed out.

### Known result: `carta_de_porte` fails schema validation today

Live E2E testing (factura and remito PASS) found that the `carta_de_porte`
Prompt Studio prompt (configured manually in task 2.2) returns different
field names than `schemas/carta_de_porte.yaml` (e.g. `nro_ctg` instead of
`nro`, `seccion_a_intervinientes` instead of `seccion_a`, and `seccion_d`
/`seccion_g` as flat strings instead of nested objects). This is a real,
observed drift between the manually-authored prompt and the versioned
schema contract, not a client or `validate.py` bug — `validate.py` reports
missing-field errors correctly for this case. Reconciling the prompt and
the schema is follow-up work outside this POC's scope.
